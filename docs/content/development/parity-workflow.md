# Parity Workflow

1. Identify the active upstream contract.
2. Record exact source refs or transcript evidence.
3. Add or refine a progress row when the behavior is not already tracked.
4. Build the smallest runtime slice with tests.
5. Update user docs only for behavior that is actually available.

Do not treat `progress.json` validation as proof that the product feature is finished. It proves the roadmap data is structurally valid.
