Gormes · Documentation

Run agents from one Go-native runtime.

Gormes gives operators a native terminal UI, offline diagnostics, provider-backed turns, local Goncho memory, the htmx dashboard, and configured gateway paths from one release binary.

What is Gormes?

A self-hosted agent runtime for machines that need to keep working.

Gormes is the Go-native rewrite of the Hermes-Agent architecture. It does not need a running Hermes backend for the native smoke path, and it keeps the operator surface inspectable: one binary, local files, explicit diagnostics, and source-backed release evidence.

  • Built for agents that restart, move machines, and cross flaky networks.
  • Useful today for offline TUI checks, provider one-shots, dashboard inspection, gateway status, and Goncho memory diagnostics.
  • Still early: full Hermes parity, broad channel parity, voice/TTS, MCP/plugin parity, and release hardening remain active roadmap work.

Quick start

Build, diagnose, then run offline

Use the inspectable source path first. Add provider or gateway credentials only after local checks pass.

  1. 1

    Build from source

    git clone https://github.com/TrebuchetDynamics/gormes-agent.git && cd gormes-agent && make build
  2. 2

    Run offline diagnostics

    ./bin/gormes doctor --offline
  3. 3

    Open the local TUI

    ./bin/gormes --offline

Configuration

Start with local files, then add credentials.

Config lives under ~/.gormes by default, with GORMES_HOME for alternate roots. Secret-like keys belong in the dotenv file, not checked-in TOML.
